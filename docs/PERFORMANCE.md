# Performance at scale

A large financial entity reports **thousands of contractual arrangements** and hundreds to
thousands of ICT third-party providers. The toolkit is profiled with a synthetic register of
**10 000 contractual arrangements and 1 000 providers** (75 925 rows across the 14
templates; generated by `dora_roi.sample.large.generate_large`, deterministic, valid).

```bash
python scripts/profile_large.py                  # 10 000 contracts / 1 000 providers
python scripts/profile_large.py --contracts 2000 --providers 300 --budget 2
```

The script times every library step and every workbench page, and exits non-zero when a
step exceeds the budget. CI runs it on every push (job *Scale test*, budget 12 s for shared
runners) so regressions are caught.

## Results

Reference machine: 4 vCPU cloud container, Python 3.13. Median of three runs, seconds.

| Step | Before | After | Change |
|---|---:|---:|---|
| Import Excel (read + parse + typed model) | 9.7 | 2.8 – 3.2 | Rust reader (python-calamine) instead of openpyxl; cheaper per-row normalisation |
| Import CSV folder | 3.6 | 2.0 | per-row overheads removed (see below) |
| Validate (63 rules) | 1.2 | 0.9 – 1.3 | LEI checks memoised; provenance read without pydantic's slow path |
| Concentration analytics | 0.3 | 0.3 | – |
| Executive summary / validation report HTML | < 0.1 | < 0.1 | – |
| Export Excel | 7.5 | 3.0 – 3.6 | XlsxWriter instead of openpyxl; written straight from the raw cells |
| Export CSV / xBRL-CSV | 0.4 / 1.1 | 0.4 / 1.1 | – |
| Workbench: upload (import + validate + overview) | 12.9 | 4.1 – 5.0 | all of the above; the form shows a busy state meanwhile |
| Workbench: inline cell edit (incremental re-parse + full re-validation) | 1.7 | 0.9 – 1.3 | |
| Workbench: every other page (fix, register, analyse, provider, renewals, compare, audit, versions) | ≤ 0.4 | ≤ 0.4 | pages are paginated; graph and schedules are linear |
| Workbench: downloads (xlsx / xBRL / executive / project) | 9.6 / 1.0 / 0.4 / 0.6 | 3.0 – 4.6 / 1.1 / 0.4 / 0.6 | |

The remaining multi-second steps are **one-off file operations** (importing a 10 000-contract
register, writing a 10 000-contract workbook) and are dominated by per-row pydantic
validation (≈ 25 µs per row) and by XlsxWriter's per-cell XML generation. Interactive work
– navigating, fixing, analysing – stays well under half a second per page.

## What was changed

| Finding | Fix |
|---|---|
| openpyxl spent ~7 s building cell objects for 530 000 cells | Read with **python-calamine** (Rust, ~0.5 s); it also rejects DTDs and custom entities, so XXE / billion-laughs files fail closed (D-045). |
| openpyxl spent ~7 s writing the workbook | Write with **XlsxWriter** in-memory mode (no temp files with client data); text via `write_string`, never as formulas. |
| Web export built a typed register (`model_construct` per row) before writing | `write_raw_workbook` writes the raw cells directly – also keeps invalid values verbatim. |
| `ROI_MAX_ROWS_PER_TABLE` read from the environment once per row | Read once per table. |
| Model pre-validator rebuilt a column dictionary for every row and used slow `isinstance` chains | Per-class cached set of textual attributes; exact type checks. |
| Code-list lookup normalised the same strings (regex) hundreds of thousands of times | Memo of exact input → member (bounded). |
| LEI checksum and explanation computed twice per code | `functools.lru_cache` on both pure functions. |
| `invalid_fields` / `row` / `source` went through pydantic's private-attribute `__getattr__` (~10× slower), read ~500 000 times per validation | Direct access to `__pydantic_private__`. |
| `RegisterOfInformation.supports_critical` rebuilt the function lookup on every call (O(contracts × functions)) in the graph and the notice schedule | `critical_checker()` builds the lookups once. |
| A 10 000-contract workspace uses ~215 MB; 20 of them could exhaust a small server | The workspace store has a **row budget** (`ROI_MAX_STORE_ROWS`, default 500 000 ≈ 6 large registers) besides the count limit; least recently used workspaces are evicted first (D-046). |
